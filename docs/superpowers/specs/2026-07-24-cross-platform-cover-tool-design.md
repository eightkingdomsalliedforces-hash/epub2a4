# 跨平台完整書封工具設計規格

日期：2026-07-24  
狀態：待使用者規格審閱

## 1. 目標

在既有 EPUB／DOCX 排版工具中新增獨立的「完整書封工具」，正式支援 Android、Windows、macOS、Linux。

工具可產生一張展開書封，固定排列為：

`封底｜書脊｜正面封面`

封面可從 EPUB 內建圖片、本機圖片或網路搜尋結果取得；程式本身不使用 AI 生成圖片。使用者可先套用自動排版，再進入視覺編輯器微調，最後獨立輸出 PDF 與 DOCX，不修改正文文件。

## 2. 非目標

第一版不包含以下功能：

- 不使用任何 AI 圖像生成服務。
- 不把封面自動插入正文 DOCX／PDF。
- 不建立或維護伺服器後端。
- 不自動檢查或下載程式更新。
- 不直接爬取任意圖片搜尋網站；一般圖片搜尋只經由使用者提供憑證的正式搜尋 API。
- 不長期保留兩套電腦 GUI；Tkinter 僅保留一個版本作過渡。

## 3. 支援平台與發佈形式

### 3.1 Android

- 保留 Kotlin、Jetpack Compose 與 Chaquopy 架構。
- 支援 Android 7.0／API 24 以上、arm64-v8a。
- 封面編輯器由 Compose 實作。
- 共用 Python 核心透過 Chaquopy 執行。

### 3.2 Windows

- PySide6／Qt 為預設 GUI。
- 使用 PyInstaller 建立免安裝目錄，再封裝為 ZIP。
- 解壓後直接啟動 `.exe`。

### 3.3 macOS

- PySide6／Qt 為預設 GUI。
- 使用 PyInstaller 建立 `.app`。
- 發佈格式為 `.app.zip`，不使用安裝程式或 DMG。

### 3.4 Linux

- PySide6／Qt 為預設 GUI。
- 以 PyInstaller 產生應用目錄，再封裝為 AppImage。
- 使用者加入執行權限後直接啟動。

### 3.5 電腦版過渡期

- `__main__.py` 預設啟動 PySide6 新介面。
- 保留 `--legacy-gui` 啟動參數，暫時開啟舊 Tkinter 介面。
- Tkinter 只保留一個大版本；完成相容性驗證後移除。
- 新舊 GUI 共用同一個轉換與封面核心，不複製商業邏輯。

## 4. 整體架構

採用「平台原生編輯器＋共用 Python 封面核心」。

### 4.1 平台層

Android Compose 與電腦 PySide6 負責：

- 檔案選取。
- 表單輸入。
- 網路搜尋與候選圖片瀏覽。
- 圖片下載、快取與本機資產管理。
- 拖曳、縮放、裁切、旋轉與文字編輯。
- 顯示尺規、出血區、裁切線、書脊邊界與黏貼區。
- 將編輯結果序列化為 `CoverProject` JSON。

### 4.2 共用 Python 核心

新增 `epub_a4_word.cover` 套件，負責：

- EPUB／DOCX／PDF 中繼資料擷取。
- 尺寸、出血、書脊、拼接與裁切幾何計算。
- 套用封面模板。
- 產生列印用高解析度畫布。
- 輸出 PDF。
- 輸出可編輯 DOCX。
- 驗證專案資料與輸出範圍。

建議模組：

- `cover/models.py`
- `cover/metadata.py`
- `cover/geometry.py`
- `cover/templates.py`
- `cover/render.py`
- `cover/pdf_export.py`
- `cover/docx_export.py`
- `cover/project_io.py`

## 5. 輸入與中繼資料

### 5.1 EPUB

自動嘗試讀取：

- 書名。
- 作者。
- 簡介／description。
- ISBN 或其他 identifier。
- 出版者。
- 語言。
- 內建封面。
- 可用插圖。
- 內容頁數或轉換後頁數。

讀取不到的欄位維持空白並允許手動補填。

### 5.2 DOCX

自動嘗試讀取：

- 文件標題屬性。
- 作者屬性。
- 文件頁數；無法可靠取得時顯示估算值並要求使用者確認。

其他資料由使用者補填。

### 5.3 PDF

自動嘗試讀取：

- PDF title／author metadata。
- 實際頁數。

其他資料由使用者補填。

## 6. 搜尋封面

### 6.1 搜尋順序

1. 以 ISBN 搜尋公開書籍資料庫。
2. 以書名＋作者搜尋公開書籍資料庫。
3. 顯示 Google Books 與 Open Library 的多張候選封面。
4. 使用者主動切換「一般圖片搜尋」時，才呼叫 Google Custom Search 圖片模式。

### 6.2 Provider 介面

搜尋服務必須實作共同介面：

```text
CoverSearchProvider.search(query, isbn, locale) -> List<SearchCandidate>
```

第一版實作：

- `GoogleBooksProvider`
- `OpenLibraryProvider`
- `GoogleCustomSearchProvider`

未來可新增其他 provider，不修改編輯器與輸出核心。

### 6.3 候選圖片

每個候選項至少包含：

- 預覽圖網址。
- 原圖網址或可取得的最大尺寸網址。
- 圖片寬高。
- 來源名稱。
- 來源頁面。
- 書名與作者比對資訊。

UI 以網格顯示多張候選圖。只有使用者選取後才下載原圖。找不到結果時可改用 EPUB 內建圖或本機圖片。

### 6.4 API 憑證

Google 一般圖片搜尋需要使用者自行輸入：

- API Key。
- Search Engine ID。

不得把共用金鑰寫入 APK、原始碼或電腦免安裝包。

儲存規則：

- Android：使用 Android Keystore 保護的加密設定。
- Windows／macOS／Linux 標準模式：優先使用系統憑證儲存服務。
- 電腦可攜模式：可選擇「只在本次執行使用」或存入 `data` 目錄；若選擇持久保存，UI 必須警告可攜資料夾中的憑證可能被其他人讀取。

## 7. 封面版面

### 7.1 支援書本尺寸

第一版正式支援現有輸出尺寸：

- A5：148 × 210 mm。
- A6：105 × 148 mm。
- 4 × 6 英吋：101.6 × 152.4 mm。

封面尺寸預設跟隨正文輸出模式，也可在獨立封面工具中手動選擇。

### 7.2 完整展開尺寸

```text
成品寬度 = 封底寬度 + 書脊寬度 + 正面寬度
畫布寬度 = 成品寬度 + 左右出血
畫布高度 = 成品高度 + 上下出血
```

預設出血為四周 3 mm，可設定為 0 至 10 mm。

### 7.3 書脊寬度

預設自動計算：

```text
紙張張數 = ceil(正文頁數 / 2)
自動書脊寬度 = 紙張張數 × 單張紙厚度
```

紙張預設值：

- 70 gsm：0.09 mm。
- 80 gsm：0.10 mm。
- 100 gsm：0.12 mm。
- 120 gsm：0.14 mm。

這些值只作估算。使用者可：

- 輸入實測單張紙厚度。
- 直接覆寫最終書脊寬度。

所有輸入值以 mm 儲存，UI 可另外顯示英吋。

### 7.4 圖片套用模式

支援兩種模式：

1. `FRONT_ONLY`：圖片只裁切到正面封面，封底與書脊由模板排版。
2. `FULL_SPREAD`：圖片延伸覆蓋封底、書脊與正面，可加模糊、暗化或漸層遮罩提高文字可讀性。

使用者可隨時切換，編輯器保留各模式的裁切參數。

### 7.5 自動模板

本機模板至少提供：

- 極簡文字版。
- 圖片正面＋純色封底。
- 全幅背景版。
- 上下色塊版。

模板自動放置：

- 正面書名。
- 正面作者。
- 書脊書名與作者。
- 封底簡介。
- 出版資訊。
- 可選 ISBN／條碼保留區。

模板只使用本機規則，不生成圖片。

## 8. 編輯器

程式先套用模板，再允許手動微調。

### 8.1 圖片操作

- 拖曳位置。
- 等比例縮放。
- 裁切。
- 旋轉。
- 水平／垂直翻轉。
- 模糊背景。
- 亮度、暗化遮罩與漸層強度。

### 8.2 文字操作

- 編輯內容。
- 拖曳位置。
- 調整字體、字級、字重、顏色、對齊與行距。
- 設定文字框寬高。
- 書脊文字可選由下往上或由上往下。
- 文字超出安全區時顯示警告。

### 8.3 輔助顯示

可切換顯示：

- 尺規。
- 正面、書脊、封底邊界。
- 3 mm 出血區。
- 安全區。
- 裁切線。
- 5 mm 黏貼重疊區。
- A4 實際紙張邊界。

預覽必須維持實際比例；桌面版另提供精確的 X、Y、寬、高數值輸入。

## 9. A4 列印與超出範圍處理

### 9.1 單張模式

當完整畫布在 1:1 尺寸下可放入 A4 橫向紙張 297 × 210 mm 時，輸出一頁完整展開書封。

不得為了塞入 A4 而自動縮小成品尺寸。

### 9.2 三頁拼接模式

當畫布寬度或高度超過 A4 可列印範圍時，自動輸出三頁：

1. 封底頁。
2. 書脊頁。
3. 正面封面頁。

規則：

- 每個部分維持 1:1 實際尺寸。
- 封底頁包含靠近書脊側 5 mm 重疊內容。
- 正面頁包含靠近書脊側 5 mm 重疊內容。
- 書脊頁兩側各包含 5 mm 重疊內容。
- 每頁加入裁切線與拼接標記。
- 裁切區外標示頁面名稱與組裝方向。
- 三頁 PDF 與三頁 DOCX 的順序固定為封底、書脊、正面。

現有 A5、A6、4×6 的單一封面部分都可放入 A4，因此第一版不再做第四層分割。

## 10. 輸出

封面永遠獨立輸出，不修改正文：

- `書名_完整書封.pdf`
- `書名_完整書封.docx`

### 10.1 PDF

- 預設 300 DPI。
- 以同一套幾何模型產生單頁或三頁輸出。
- 預設嵌入高解析度列印畫布，確保 Android 與電腦版結果一致。
- Android 記憶體不足時可選擇 200 DPI；不得默默降低解析度。
- PDF 頁面尺寸必須是精確 A4，不使用印表機驅動縮放。

### 10.2 DOCX

- 頁面尺寸為 A4，邊界設為 0。
- 圖片、文字框、書脊文字與裁切標記使用獨立的絕對定位物件。
- 使用者可在 Word／LibreOffice 中修改文字、替換圖片與微調位置。
- 不把整頁只輸出成一張不可編輯圖片。
- 若某些 Word 功能在不同辦公軟體顯示不同，PDF 作為列印基準。

## 11. 使用流程

### 11.1 轉換完成後進入

1. EPUB／DOCX 轉換完成。
2. 顯示「製作獨立書封」。
3. 自動帶入正文尺寸、頁數、書名與作者。
4. 使用者選圖、套模板、編輯並輸出。

### 11.2 首頁獨立入口

1. 點選「封面工具」。
2. 選擇 EPUB、DOCX 或 PDF。
3. 程式擷取中繼資料。
4. 使用者確認正文尺寸、頁數與紙張厚度。
5. 選擇 EPUB 內建圖、本機圖或網路候選圖。
6. 自動排版後進入編輯器。
7. 獨立輸出 PDF 與 DOCX。

### 11.3 離線使用

沒有網路時：

- EPUB／DOCX／PDF 解析可正常使用。
- 可使用 EPUB 內建封面、本機圖片與本機模板。
- 搜尋頁顯示離線狀態，不阻止其他功能。

## 12. 專案資料模型

平台 UI 與 Python 核心使用 UTF-8 JSON 交換資料。

主要模型：

```text
CoverProject
  schema_version
  source_file
  source_type
  metadata
  trim_size_mm
  page_count
  paper_caliper_mm
  auto_spine_width_mm
  manual_spine_width_mm
  bleed_mm
  overlap_mm
  image_mode
  background
  elements[]
  export_settings
```

每個 `CoverElement` 包含：

- 唯一 ID。
- 類型：image、text、shape、barcode-placeholder、guide。
- 所屬區域：back、spine、front、spread。
- X、Y、寬、高，全部使用 mm。
- rotation、z-index、opacity。
- 類型專屬設定。

`schema_version` 用於未來遷移；第一版為 `1`。

## 13. 網路、隱私與錯誤處理

- 只有使用者主動搜尋時才連線。
- 不上傳 EPUB、DOCX 或 PDF 原始文件。
- 搜尋只傳送書名、作者、ISBN 或使用者輸入的關鍵字。
- 所有網路請求只允許 HTTPS。
- 限制下載圖片檔案大小與像素尺寸，拒絕非圖片內容。
- 縮圖使用快取；使用者選取的原圖複製到工作目錄。
- UI 顯示圖片來源，並提醒使用者自行確認授權與使用權。
- API 配額用完、憑證錯誤、逾時、無結果、圖片解碼失敗都要提供可理解的錯誤訊息。
- 搜尋失敗不得影響本機封面製作。

## 14. 電腦版設定與可攜模式

標準模式設定位置遵循作業系統的使用者資料目錄。

可攜模式：

- 程式旁存在 `portable.flag` 時啟用。
- 設定、快取與工作資料寫入程式旁 `data/`。
- 程式位於唯讀位置時，顯示錯誤並提供切回標準模式的選項。
- 手動更新時，標準模式設定不受程式資料夾替換影響。
- 程式不執行版本檢查或自動更新。

## 15. 測試策略

### 15.1 共用核心

- EPUB／DOCX／PDF 中繼資料 fixture 測試。
- 書脊計算邊界測試。
- A4 單頁／三頁判定測試。
- 5 mm 重疊與裁切線座標測試。
- CoverProject JSON schema 測試。
- 模板套用測試。
- PDF 頁面尺寸、頁數與像素尺寸測試。
- DOCX 頁面尺寸與定位物件 XML 測試。
- 同一 CoverProject 在 Android 與電腦輸出的幾何誤差不得超過 0.1 mm。

### 15.2 搜尋

- 使用錄製 fixture，不在一般單元測試呼叫真實 API。
- 測試無憑證、錯誤憑證、配額不足、逾時、空結果與損壞圖片。
- 測試 provider 切換與結果去重。

### 15.3 Android

- Compose 狀態與 ViewModel 單元測試。
- 候選圖選取、拖曳、縮放及輸出流程 instrumented test。
- Android 7、主流新版 Android 與 arm64 實機煙霧測試。
- 低記憶體 PDF 匯出測試。

### 15.4 電腦版

- PySide6 視窗啟動與主要流程 smoke test。
- Windows、macOS、Linux 打包產物啟動測試。
- `--legacy-gui` 過渡入口測試。
- 標準模式與可攜模式設定路徑測試。

## 16. 實作階段

建議分成四個可獨立驗收的階段：

1. 共用資料模型、幾何、模板、PDF／DOCX 匯出。
2. 電腦 PySide6 遷移與封面編輯器。
3. Android Compose 封面編輯器與 Chaquopy 整合。
4. 網路搜尋 provider、憑證設定及三平台免安裝打包。

第一階段完成前，不先製作兩套不同的版面計算器。

## 17. 驗收條件

功能完成必須同時符合：

1. Android、Windows、macOS、Linux 都能從 EPUB 製作封底／書脊／正面完整書封。
2. DOCX 與 PDF 可從獨立入口製作封面。
3. 可使用 EPUB 內建圖片、本機圖片及多張網路候選圖片。
4. 程式不生成圖片，也不需要伺服器。
5. 可切換正面圖片模式與全幅背景模式。
6. 自動書脊計算、紙張預設、實測厚度與手動覆寫皆可使用。
7. 完整書封可放入 A4 時輸出一頁；超出時保持 1:1 尺寸輸出封底、書脊、正面三頁。
8. 三頁輸出包含 5 mm 重疊區、裁切線與拼接標記。
9. PDF 與 DOCX 均可獨立輸出；DOCX 中主要文字與圖片可編輯。
10. 標準模式不把 API 金鑰寫入程式目錄或發佈包。
11. Windows ZIP、macOS app.zip、Linux AppImage 均可免安裝啟動。
12. PySide6 為預設介面，Tkinter 備用入口僅保留一個版本。
13. 程式不檢查或自動下載更新。
