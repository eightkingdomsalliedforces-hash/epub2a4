# Word 封面安全頁邊距設計

## 問題

封面工具輸出的 DOCX 將每個列印頁面的上下左右頁邊距設為 `0 mm`。
Microsoft Word 會依目前選用印表機的不可列印區判定這個設定過小，因而顯示
「邊界過小，列印時可能會剪掉部分內容」警告。

封面、書脊、封底與裁切線都使用相對於實體頁面的絕對座標定位，因此不需要
依賴零頁邊距來維持位置。

## 目標

- 封面 DOCX 在 Word 中使用通常可被印表機接受的安全頁邊距。
- 保持紙張尺寸、方向、分頁數量及所有封面物件的絕對座標不變。
- 保留裁切線、圖片裁切、書脊、封底和可編輯文字。
- 不影響 PDF、PNG 或一般內文 DOCX 匯出。

## 設計

在封面 DOCX 匯出器的 section 設定中：

- 上、下、左、右頁邊距統一設為 `12.7 mm`（半英吋）。
- 頁首距離、頁尾距離及裝訂邊維持 `0`。
- 紙張寬高與直向／橫向設定維持原值。
- 所有圖片、文字方塊、圖形及裁切線繼續以頁面為基準使用絕對座標，不減去
  頁邊距，也不縮放內容。

`12.7 mm` 比 `5 mm` 更能涵蓋不同印表機的不可列印區，同時不會改變絕對定位
物件的輸出幾何。

## 相容性與錯誤處理

- 舊專案不需遷移；頁邊距只在重新匯出 DOCX 時產生。
- 若實體印表機本身不支援滿版列印，超出硬體可列印區的內容仍可能被硬體裁掉；
  本次修正的範圍是避免 DOCX 以零頁邊距主動觸發 Word 警告。
- 使用者關閉裁切線時，既有隱藏行為維持不變。

## 測試

- 驗證每個封面 DOCX section 的上下左右頁邊距都是對應 `12.7 mm` 的 OOXML
  twips 值。
- 驗證頁首、頁尾與裝訂邊仍為零。
- 驗證 A4 紙張尺寸、方向及 section 數量不變。
- 驗證圖片與文字的錨點仍相對頁面定位，裁切線座標與數量不變。
- 執行完整 Python 與桌面測試；Android 不修改程式碼，但仍以既有測試確認共用
  Python 匯出器沒有整合回歸。
