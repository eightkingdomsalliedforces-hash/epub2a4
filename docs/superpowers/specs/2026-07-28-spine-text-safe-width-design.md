# 書脊文字與 Logo 可見度修復設計

## 問題

`v0.6.3` 對書脊左右固定套用各 `3 mm` 的折線安全距離。使用者的
133 頁書籍搭配每張 `0.090 mm` 紙張厚度時，自動書脊寬度為
`ceil(133 / 2) × 0.090 = 6.030 mm`。固定邊距扣除後，書脊文字區只剩
`0.030 mm`，因此標題、作者與出版社在編輯器及輸出中完全看不到。

這是書脊安全區幾何的臨界值錯誤，不是文字顏色、字型或圖層問題。

## 修復範圍

- 封面與封底靠近折線的一側仍保留既有 `3 mm` 安全距離。
- 書脊內部文字區改用自適應水平邊距。
- 書脊 Logo 放大並維持原比例與置中。
- 不改變書脊實際寬度、折線位置、背景或直排方向。
- Desktop 與 Android 共用相同核心幾何，因此兩端會同時取得修復。

## 幾何規則

書脊每側的水平安全邊距為：

```text
min(1.0 mm, 書脊寬度 × 0.12)
```

此規則提供接近實體書脊參考圖的可讀範圍，同時保留基本折線容差：

- `4.000 mm` 書脊：每側 `0.480 mm`，可用寬度 `3.040 mm`
- `6.030 mm` 書脊：每側 `0.724 mm`，可用寬度約 `4.583 mm`
- `8.000 mm` 書脊：每側 `0.960 mm`，可用寬度 `6.080 mm`
- `12.000 mm` 書脊：每側 `1.000 mm`，可用寬度 `10.000 mm`

垂直安全距離維持上下各 `5 mm`。

## 書脊 Logo 規則

現有 Logo 寬度為書脊的 `70%`，在 `6.030 mm` 書脊上只有 `4.221 mm`，
難以辨識。新規則將 Logo 寬度調整為書脊寬度的 `90%`，高度上限由
`14 mm` 調整為 `18 mm`。

Logo 使用 `contain` 保持原始比例並水平置中。Logo 的實際矩形必須完整
落在書脊矩形內，不可只依靠裁切遮住超出的部分。`6.030 mm` 書脊的
Logo 顯示寬度將約為 `5.427 mm`。

## 資料流

`calculate_layout()` 依頁數與紙張厚度算出實際書脊寬度，再由
`_spine_safe_rect()` 產生自適應安全區。`build_spine_slots()` 繼續依
既有 full／compact／minimal 級距，在該安全區配置標題、集數、作者與
出版社。模板、Desktop 畫布、Android 預覽及匯出流程都使用這組共享座標。

## 測試與驗收

- 精確重現 `133 頁 × 0.090 mm = 6.030 mm`，確認文字區寬度約
  `4.583 mm`，而不是 `0.030 mm`。
- 驗證 `4 mm`、`6.03 mm`、`8 mm`、`12 mm` 書脊安全區皆為正值並符合
  自適應公式。
- 驗證 6.03 mm compact 模板的書脊標題、作者與出版社元素具有可讀寬度，
  且保持在實際書脊範圍內。
- 驗證 6.03 mm 書脊 Logo 寬度約為 `5.427 mm`、高度上限為 `18 mm`、
  保持置中且不超出書脊。
- 對每個書脊文字與 Logo 元素檢查 `x`、`y`、右邊界與下邊界，全部必須
  位於 `spine_rect` 內。
- 執行完整 Python 與 Desktop 測試，建置 Android APK 與 Windows
  Portable。
