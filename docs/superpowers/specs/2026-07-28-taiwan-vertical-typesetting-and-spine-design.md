# 台灣直排正文與平衡出版社式書脊設計

日期：2026-07-28  
目標版本：v0.8.0  
平台：Windows Desktop、Android、共享 Python 核心

## 1. 目標

轉換工具新增符合台灣直排書籍閱讀習慣的正文模式，並將它設為 Desktop 與 Android 新轉換工作的預設值。正文在每頁由右上開始，字由上往下排列，欄位由右往左推進，整本書採右裝訂及由右往左翻頁。

同一版本修正 v0.7.0 的參考堆疊書脊。新版採使用者選定的「A：平衡出版社式」，解決主標太小、資訊集中在頂端、中段大量空白、出版社資訊重複及 Logo 周圍文字越界等問題。

## 2. 已確認的產品決策

- 提供 `台灣直排` 與 `橫排` 兩種正文模式。
- Desktop 與 Android 的新轉換預設為 `台灣直排`。
- 台灣直排預設使用右裝訂；橫排預設使用左裝訂。
- 直排中文保持直立。
- 標點採 Microsoft Word 原生直排字形與位置。
- 英文及較長數字依 Microsoft Word 原生直排規則旋轉，不逐字強制直立。
- 插圖保持正常方向，不隨正文旋轉。
- 舊呼叫端未提供新欄位時維持舊版橫排行為，確保 API 與舊工作流程相容。
- 書脊採「平衡出版社式」。
- 書脊頂端只顯示出版社 Logo；Logo 周圍不顯示出版社簡稱或任何額外文字。
- 出版社名稱只在書脊底部出現一次。
- 書脊所有內容必須限制於實際書脊矩形內。

## 3. 使用者介面

### 3.1 Desktop

轉換頁新增「正文方向」控制：

- `台灣直排（右裝訂）`，預設。
- `橫排（左裝訂）`。

選擇台灣直排時，版面預覽顯示右起欄位、由上往下的閱讀箭頭及「右裝訂」標示。既有字體、字級、行距、段後距、頁碼及裁切線選項繼續可用；在直排模式中，「行距」實際控制欄距。

### 3.2 Android

轉換設定使用與 Desktop 相同的兩個選項、預設值和說明文字。Android 只傳遞共享設定，不自行計算直排頁容量或拼版順序。

### 3.3 相容性提示

輸出以 Microsoft Word 的原生 OOXML 直排支援為準。選擇直排時，介面顯示一次簡短提示：LibreOffice、Google Docs 或其他閱讀器可能無法完整呈現直排標點及混合英文方向；不將此提示視為錯誤。

## 4. 共享資料模型

`LayoutSettings` 與跨平台 JSON 新增：

```text
writing_mode: "taiwan_vertical" | "horizontal"
binding_direction: "right" | "left"
```

規則：

- 共享資料模型缺少欄位時，預設 `horizontal` 及 `left`，保護舊程式呼叫。
- Desktop 與 Android 建立新請求時，明確送出 `taiwan_vertical` 及 `right`。
- 驗證拒絕未知值。
- `taiwan_vertical + left` 與 `horizontal + right` 保持可表達，以免未來擴充受限；目前 UI 僅提供已確認的兩組配對。

## 5. 直排版面核心

### 5.1 EPUB 路徑

EPUB 仍解析成既有 `TextBlock`、`TextRun`、`ImageBlock`。直排不改寫原文，不插入逐字換行，也不把正文轉成圖片。

直排頁容量使用兩個軸計算：

- 每欄字數由可用頁高、字級及字元前進量決定。
- 每頁欄數由可用頁寬、字級及欄距決定。

分頁器必須保持：

- 所有文字原順序與內容不遺失。
- 段落邊界、粗體、斜體及標題語意。
- 明確換頁。
- 插圖與其相鄰文字的先後順序。

一般正文首行縮排兩個全形字；引文保留獨立縮排；章標題放大、置於右起首欄，且可要求從新頁開始。

### 5.2 Word 來源路徑

Word 重排保留原有段落、文字 run 格式、圖片及手動換頁。台灣直排模式使用 WordprocessingML 原生文字方向，不透過逐字表格或文字方塊模擬。

### 5.3 OOXML

- EPUB 產生的迷你頁內容在其 Word 表格儲存格設定 `w:textDirection w:val="tbRl"`。
- Word 重排路徑在適當的節或內容容器設定等價的 `tbRl` 方向。
- 段落與 run 繼續保留 East Asia 字型。
- 插圖所在段落不旋轉圖片本身。
- 橫排模式不輸出直排方向屬性。

## 6. 右裝訂與拼版

`binding_direction="right"` 由共享拼版核心處理，不由 UI 或 DOCX 寫入器各自反轉。

- 邏輯閱讀順序保持第 1、2、3 頁。
- 實體紙張的左右槽位依右裝訂規則鏡像。
- `signature16`、`four_up`、`b6_on_a5` 及單頁輸出均使用同一 binding 設定。
- 空白補頁仍放在簽帖尾端，不改變正文順序。
- 右裝訂頁碼的內外側位置與左裝訂鏡像；頁碼文字本身保持可讀，不旋轉成側躺。
- 裁切線、摺線及拼接標記沿用共享幾何，不因左右鏡像而越界或重複。

## 7. 插圖規則

- 單頁插圖保持原始上方朝向。
- 直式、橫式圖片均按現有等比例縮放規則限制於內容安全區。
- 圖片不套用 `tbRl` 旋轉。
- 圖片說明文字若存在，使用直排正文規則。
- 圖片缺失時的替代文字仍保留在原位置並採直排。

## 8. 平衡出版社式書脊

`reference_stacked` 更新為已批准的 A 款；其他兩種書脊樣式保留。

由上至下的視覺層級：

1. 出版社 Logo：頂端水平置中，四周保留安全距離；不得附加「川」、出版社簡稱或其他文字。
2. 主書名：使用中央主要空間，為最大、最醒目的直排文字。
3. 卷數：獨立圓章，使用自動擷取或手動指定的封面主題色。
4. 作者：位於書脊下段，字級小於主書名但保持可讀。
5. 內部書號：靠近左下安全區；空白時不保留佔位。
6. 出版社名稱：最底部水平置中，只出現一次。

Logo 使用原始圖檔的 `contain` 比例，最大寬度不超過書脊安全寬度，且裁切至書脊區域。不得另外從出版社名稱產生文字 Logo。

### 8.1 寬度降級

- `>= 10 mm`：完整資訊；可包含英文書名，但英文書名不得搶占主書名空間。
- `6–10 mm`：省略英文書名，保留 Logo、主書名、卷數、作者及出版社。
- `< 6 mm`：再省略內部書號；縮短作者區；主書名維持優先。
- 若剩餘高度不足，依序縮小作者、出版社、主書名，但不得低於可讀下限。
- 最終無論任何寬度，元素矩形及實際繪製像素都不得超出 `spine_rect`。

## 9. 錯誤處理

- 不支援的 writing 或 binding 值回傳明確驗證錯誤。
- 字型不支援必要直排字形時，使用既有 East Asia 字型回退並加入警告。
- 內容容量估算無法安全放置一個字元時停止輸出並回報版面設定過小，不靜默遺失文字。
- 不相容的第三方 Word 閱讀器只產生相容性提醒，不阻止輸出。
- 書脊 Logo 讀取失敗時略過 Logo 並顯示警告，不以額外文字替代。

## 10. 測試與完成條件

### 10.1 共享核心

- 新舊設定的序列化、缺省值及驗證。
- 固定中文段落的第一欄位於最右側，後續欄位向左。
- 混合中文、英文、數字和標點不遺失、不重新排序。
- 章標題、正文縮排、引文及手動換頁。
- 插圖保持原方向。
- 右裝訂的已知頁序，涵蓋奇偶頁、補白頁及所有拼版模式。
- 左裝訂橫排的既有黃金測試保持不變。

### 10.2 DOCX

- 直排內容存在 `w:textDirection w:val="tbRl"`。
- 橫排內容不存在該屬性。
- 圖片 relationship、段落文字及 run 格式保持完整。
- 頁碼位置符合右裝訂鏡像規則。
- 產物可由 `python-docx` 重新開啟，且封裝部件完整。

### 10.3 Desktop 與 Android

- 兩端預設顯示台灣直排。
- 選擇橫排後送出 `horizontal + left`。
- 選擇台灣直排後送出 `taiwan_vertical + right`。
- 預覽標示與實際請求一致。

### 10.4 書脊

- 頂端 Logo 周圍沒有任何文字元素。
- 出版社名稱只存在一個書脊元素，且位於底部。
- 主書名字級大於作者及出版社。
- 三個寬度級距的所有元素都在書脊內。
- 圓章使用目前有效主題色。
- Raster、PDF、DOCX 及 Desktop 預覽使用同一書脊配置。

### 10.5 發佈

- Python、Desktop、Android 全部測試通過。
- Windows Portable 實際啟動 smoke test 通過。
- 版本更新為 v0.8.0。
- 推送 `v0.8.0` 標籤後，自動 Release 必須包含：
  - `EPUB2A4-Android.apk`
  - `EPUB2A4-Windows-Portable-x64.zip`
  - `SHA256SUMS.txt`

## 11. 非目標

- 不將正文轉成圖片或 PDF 以假裝直排。
- 不實作逐字文字方塊或每字一格的模擬直排。
- 不保證 Google Docs、LibreOffice 或手機預覽器與 Microsoft Word 像素一致。
- 不在此版本加入新的封面模板；只修正既有 `reference_stacked`。
- 不移除橫排模式或破壞舊版 API 缺省行為。
