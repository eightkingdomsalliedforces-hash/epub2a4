# 出版社封底、書脊可讀性與標籤發佈設計

## 目標

修正 Windows/macOS/Linux PySide6 桌面版與 Android Compose 封面工具的出版社封底流程，並在推送版本標籤時自動建立 GitHub Release。使用者提供的書籍照片是書脊排版方向、字級層次與底部出版社識別位置的驗收參考。

## 範圍

### 共用封面核心

- `publisher_back_matter` 模板只建立一組封底出版社資訊與一個 Logo 槽位；重新套用模板會替換舊模板元素，不會留下第二組資訊。
- Logo 是可替換的封底圖片元素。所有平台都經由相同核心操作更新專案 JSON，因此 PDF、DOCX、桌面預覽與 Android 專案資料一致。
- 書脊採印刷可讀性優先的規則：中文使用直排；包含拉丁字元的副標題採旋轉 90 度的單行直向排法。窄於安全門檻時先省略副作者與次要資訊，再調整字級，絕不把主要標題縮至不可讀。
- 出版社封底的 ISBN、出版社、定價、出版／代理資訊與譯者使用明確的印刷字級下限；空值不產生佔位文字。

### 桌面版

- 封面來源列採固定的水平版面：路徑欄可伸縮，「瀏覽…」按鈕不可被壓出可視範圍。
- 出版社資料編輯器只能存在一份，並隨目前專案／模板同步。
- 「搜尋出版社 Logo」用出版社名稱發出搜尋並顯示候選；選取候選後下載、嵌入並置入封底 Logo 槽位。
- 「手動選擇 Logo」開啟圖片檔案選擇器；選取後立即嵌入並更新預覽。

### Android

- 在出版社封底設定中提供同一組資料欄位與單一 Logo 槽位。
- 提供從裝置選取 Logo 的流程並立即更新預覽；若目前 Android 搜尋基礎設施未支援可信的 Logo 網路來源，搜尋控制項會清楚顯示限制且不以無作用按鈕呈現。
- 書脊 Canvas 依共用的文字方向與可讀性規則渲染。

### GitHub Release

- 新增 GitHub Actions 工作流程，在推送符合 `v*` 的 tag 時觸發。
- 建置既有 Windows portable EXE 與 Android release APK。
- 對所有上傳產物產生 SHA-256 檔案。
- 使用 tag 名稱建立 GitHub Release，附上 Windows ZIP、Android APK、雜湊檔與自動產生的版本說明。
- 非 tag 的 `main` 推送維持既有 CI，不建立 Release。

## 非目標

- 不重新設計整個封面編輯器或新增未驗證的付費 Logo API。
- 不把書脊固定做成單一書籍的像素複製；使用參考圖的資訊層級與閱讀方向，保留不同尺寸書籍所需的自適應排版。

## 驗收與測試

- 桌面測試覆蓋瀏覽按鈕可見、Logo 搜尋／本機選擇能建立或替換單一 Logo 元素、重套模板不重複出版社資料。
- 核心測試覆蓋書脊文字方向、字級下限及窄書脊的省略規則。
- Android 單元測試覆蓋出版社模板、Logo 更新後的 JSON 與書脊資料。
- CI 工作流程檢查 tag 條件、產物名稱、Release 上傳與雜湊步驟。
- 全套 Python、桌面與 Android 測試，並人工檢視一份以參考書脊資訊製作的匯出預覽。
