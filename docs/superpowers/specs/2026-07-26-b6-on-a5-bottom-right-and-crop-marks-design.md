# B6 內容置於 A5 右下角與全模式裁切線設計

日期：2026-07-26

## 問題

目前 `b6_on_a5` 模式將 B6 內容放在 A5 紙張上，但沒有利用紙張右邊與下邊作為天然成品邊；使用者仍需處理多個方向的裁切。另一方面，部分正文輸出模式雖已有裁切線相關資料結構或選項，實際產出的 DOCX／列印頁面沒有穩定顯示正確裁切線。

## 目標

1. `b6_on_a5` 模式固定使用直向 A5 紙張（148 × 210 mm）承載直向 B6 成品（128 × 182 mm）。
2. B6 成品框固定貼齊 A5 的右邊與下邊，因此成品框左上角位於 `(20 mm, 28 mm)`。
3. A5 的右邊與下邊直接視為 B6 成品邊，不建立右側或下側裁切線。
4. 在 `y=28 mm` 與 `x=20 mm` 建立兩條完整裁切線，讓裁刀分別沿水平方向與垂直方向各裁一次。
5. 所有正文輸出模式都由同一套裁切線規劃器判定需要顯示的裁切邊，不再由各 DOCX 寫入路徑自行猜測。
6. 桌面版所有相關模式完成並通過測試後，才開始 Android 介面移植。

## 非目標

- 不縮放 B6 成品內容。
- 不讓使用者選擇 B6 在 A5 上的位置；`b6_on_a5` 自動採用右下角。
- 不在與紙張邊緣重合的成品邊上畫沒有用途的額外裁切線。
- 不新增需要使用者理解的右下角開關。

## 版面幾何

座標原點採紙張左上角，單位為毫米。

- A5 紙張：`148 × 210`
- B6 成品：`128 × 182`
- B6 左側空白：`148 - 128 = 20`
- B6 上方空白：`210 - 182 = 28`
- B6 目的矩形：`x=20, y=28, width=128, height=182`
- B6 右邊：`148`，與紙張右邊重合
- B6 下邊：`210`，與紙張下邊重合

裁切導線固定為兩條完整直線：

- 水平導線：從 `(0, 28)` 到 `(148, 28)`。
- 垂直導線：從 `(20, 0)` 到 `(20, 210)`。

兩條導線在 `(20, 28)` 相交，該交點就是 B6 成品左上角。如此可使用裁刀完成一次水平裁切與一次垂直裁切。

## 統一裁切線模型

正文排版核心使用與渲染器無關的裁切線規劃結果：

```python
@dataclass(frozen=True)
class CropGuide:
    x1_mm: float
    y1_mm: float
    x2_mm: float
    y2_mm: float
    role: Literal["crop", "fold"] = "crop"

@dataclass(frozen=True)
class PagePlacement:
    paper_width_mm: float
    paper_height_mm: float
    content_x_mm: float
    content_y_mm: float
    content_width_mm: float
    content_height_mm: float
    guides: tuple[CropGuide, ...]
```

`page_placement.py` 負責產生 `PagePlacement`；`docx_writer.py` 只依照結果建立內容位置與線條，不自行重新計算。

## 各輸出模式規則

### `b6_on_a5`

- 內容固定置於右下角。
- 裁切線開啟時，產生一條跨越 A5 全寬的水平裁切線，以及一條跨越 A5 全高的垂直裁切線。
- 右邊與下邊因與紙張邊緣重合，不產生額外裁切線。

### `single_a5`

- 成品與 A5 紙張相同大小時，四邊皆為天然紙張邊。
- 不產生內部裁切線。

### `single_4x6`

- 使用實際 4 × 6 英吋紙張且成品與紙張相同大小時，不產生內部裁切線。

### `four_up`

- 每個成品格的內部切割邊必須可見。
- 相鄰格共用的切割線只建立一次，避免重複加粗。
- 與紙張外邊重合的邊不另外畫線。

### `signature16`

- 保留裝訂折頁與頁序邏輯。
- 明確區分裁切線與折線；裁切線使用實線，折線使用虛線或既有折線樣式。

## 裁切線視覺規則

- 線條使用細黑線，固定為 `0.35 pt`。
- 正式輸出與預覽必須使用相同座標結果。
- 使用者關閉「裁切線」時，內容位置仍保持右下角，只是不渲染導線。

## 相容性與設定

- 保留現有輸出模式名稱 `b6_on_a5`。
- 現有「顯示裁切／折線」設定繼續控制是否顯示裁切線；幾何位置不受該設定影響。
- 舊設定檔無需遷移。

## 測試要求

1. 核心測試驗證 B6-on-A5 的目的矩形精確為 `(20, 28, 128, 182)`。
2. 核心測試驗證導線精確為 `(0,28)→(148,28)` 與 `(20,0)→(20,210)`。
3. DOCX 測試解析頁面與繪圖 XML，確認內容位於右下角且兩條完整裁切線存在。
4. 測試裁切線關閉時仍保持右下角位置。
5. 為 `single_a5`、`single_4x6`、`four_up`、`signature16` 建立模式矩陣，確認每種模式的必要裁切線／折線都被渲染。
6. Windows、macOS、Linux 共用 Python 測試全部通過。
7. Android APK 建置與實際 DOCX 渲染驗證通過。
