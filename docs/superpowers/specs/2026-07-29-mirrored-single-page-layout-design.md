# 漫畫單頁奇偶鏡像排版設計

## 問題

目前 `single_a5`、`single_4x6` 與 `b6_on_a5` 都使用一張跨越所有輸出頁面的
單欄表格。頁碼能依奇偶頁換邊，但表格本身只能使用單一對齊方式，因此每頁的
內容塊都固定在同一側。`b6_on_a5` 的裁切線也放在重複頁首中，所有頁面只能
共用同一組座標。

實際出版社排版需要左右頁互為鏡像：奇數頁內容靠右、偶數頁內容靠左，裝訂側
留白隨頁面換邊。

## 適用範圍

鏡像規則套用於所有單頁輸出模式：

- `single_a5`
- `single_4x6`
- `b6_on_a5`

四頁拼版與十六頁摺手模式維持既有拼版和裝訂方向邏輯。

## 頁面規則

- 奇數頁：內容塊靠紙張右側，未使用的水平空間位於左側。
- 偶數頁：內容塊靠紙張左側，未使用的水平空間位於右側。
- 奇偶判定優先使用 `MiniPage.logical_page_number`。
- 若頁面沒有邏輯頁碼，使用輸出中的一基底實體頁序作為後備值。
- 這個內容塊位置規則不受 `binding_direction` 改變；它是使用者明確指定的
  出版版面規則。
- 現有頁碼對齊仍依 `binding_direction` 運作，不因內容塊鏡像而改變。

內容塊的寬度、高度、內距、字級、圖片尺寸和上下位置都維持原值。只有整個
內容塊的水平位置改變。

## DOCX 結構

單頁模式不再用一張多列表格承載所有頁面。改為：

1. 每個輸出頁建立一個零高度的頁面前置段落。
2. 第一頁沿用第一個段落；後續頁的前置段落設定 `page_break_before`。
3. 每個前置段落後建立一張一列一欄的固定寬度表格。
4. 奇數頁表格設為靠右，偶數頁表格設為靠左。
5. 每張表格只承載該頁的 `MiniPage`，避免跨頁列高或分割造成空白頁。

section 的上下頁邊距維持既有值；左右頁邊距改為零，讓固定寬度表格能在完整
紙張寬度內靠左或靠右。內容塊寬度仍由已解析的 `cell_width_cm` 決定，因此
原本左右頁邊距占用的總空間會集中到當頁的單一側。

## 裁切線

只有目前已提供單頁裁切線的 `b6_on_a5` 受影響：

- 每頁水平線維持從 `(0, 28)` 到 `(148, 28)` mm。
- 奇數頁內容位於 `x = 20..148` mm，垂直線位於 `x = 20` mm。
- 偶數頁內容位於 `x = 0..128` mm，垂直線位於 `x = 128` mm。

裁切線不再放進重複頁首，而是錨定到每頁的前置段落，座標仍相對實體頁面。
VML 與 DrawingML 兩種導線格式共用相同的逐頁寫入介面。

`single_a5` 與 `single_4x6` 不新增原本不存在的裁切線。

## 相容性

- Desktop 與 Android 都使用共用 Python DOCX 產生器，兩端同步生效。
- 不修改 EPUB 解析、分頁容量、PDF、封面工具或多頁拼版。
- 使用者關閉裁切線時不建立任何逐頁導線。
- 既有右裝訂／左裝訂頁碼位置維持不變。

## 測試

- 純幾何測試驗證三種單頁模式的奇數靠右、偶數靠左。
- DOCX 測試驗證每頁各有一張表格，對齊順序為右、左、右。
- 驗證三頁輸入仍產生三頁，不新增空白頁。
- B6 VML 與 DrawingML 測試驗證奇數頁垂直線為 `20 mm`、偶數頁為
  `128 mm`，水平線維持 `28 mm`。
- 驗證關閉裁切線後不輸出任何逐頁導線。
- 完整執行 Python、Desktop 與 Android 測試。
