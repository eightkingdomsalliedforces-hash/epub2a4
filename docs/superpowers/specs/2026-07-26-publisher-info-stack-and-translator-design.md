# 出版資訊自動堆疊與譯者欄位設計

日期：2026-07-26

## 問題

目前出版社式封底右側的「出版社名稱」與「出版資訊」使用兩個固定高度文字框。這會造成：

- 出版社名稱和下面各行的左邊界、基線與行距不一致。
- 缺少價格、代理或其他資料時，固定文字框仍保留高度，形成不自然的大面積空白。
- 字體候選未包含使用者實際安裝的華康中圓體名稱 `DFPYuanW5-GB`，因此會錯誤回退到一般系統字體。
- 封面編輯器與正式輸出的文字度量可能不同，導致預覽與 PDF／DOCX 的排列不一致。
- 專案資料模型缺少獨立的譯者欄位，無法重現參考圖中的「譯者：……」。

## 目標

1. 將右側出版資訊排成緊湊、靠左且無多餘空白的垂直資訊群。
2. 所有可見行使用相同左邊界，並由實際字型度量決定高度與行距。
3. 缺少的資料行完全不佔空間，後續行自動上移。
4. 正確優先匹配 `DFPYuanW5-GB` 與 `DFPYuanW3-GB`。
5. 新增可選的譯者欄位，並保持 schema-v1 舊專案相容。
6. 編輯器、完整預覽、PDF 與 DOCX 共用同一套版面計算結果。
7. 出版資訊群仍可整組移動、縮放、隱藏與刪除。

## 非目標

- 不下載、生成或打包任何商業字型檔。
- 不把整個出版資訊區轉成圖片。
- 不修改 ISBN／EAN 的編碼規則。
- 不要求未安裝華康字型的電腦達到像素級相同；未安裝時使用明確的回退字體。
- 不重新設計封面其他文字元素。

## 資料模型

在 `CoverMetadata` 新增：

```python
translator: str = ""
```

專案 JSON 繼續使用 schema version 1：

- 載入舊專案時，缺少 `translator` 視為空字串。
- 儲存新專案時寫出 `translator`。
- 空字串不產生封底文字行。

出版資訊元素使用既有 `TEXT` 元素，不增加新的 `ElementKind`。模板產生兩個文字元素：

- `back-publisher-heading`：出版社名稱。
- `back-publisher-details`：價格、代理／出版地、譯者等細節行。

兩個元素的 `content` 加入：

```json
{
  "group_id": "publisher-info-stack",
  "layout_role": "heading | details"
}
```

這些欄位放在既有可擴充的 `content` 字典中，因此不需要 schema 升級。

## 顯示內容與順序

資訊群依序建立：

1. 出版社名稱，例如 `台灣角川`。
2. 價格，例如 `定價：NT$110/HK$35`。
3. 代理或出版地，例如 `香港代理：角川洲立出版`。
4. 譯者，例如 `譯者：李彥樺`。

規則：

- 每個值先去除首尾空白。
- 空值不建立行，也不保留垂直間距。
- 譯者欄位只儲存名稱；模板顯示時自動加上 `譯者：`。
- 若使用者輸入的譯者內容已以 `譯者：` 或 `譯者:` 開頭，不重複加前綴。
- 出版社名稱缺少時，細節行仍可顯示，並直接從資訊群頂端開始。
- 所有行保持靠左，不做兩端對齊或水平置中。

## 字體候選

### 出版社名稱

依序偵測：

1. `DFPYuanW5-GB`
2. `DFPYuanW5`
3. `DFP Yuan W5`
4. `DFYuan-W5`
5. `華康中圓體`
6. `華康圓體 Std W5`
7. `Yuanti TC`
8. `PingFang TC`
9. `Microsoft JhengHei UI`
10. `Noto Sans CJK TC`
11. `Noto Sans TC`

### 出版資訊

依序偵測：

1. `DFPYuanW3-GB`
2. `DFPYuanW3`
3. `DFP Yuan W3`
4. `DFYuan-W3`
5. `華康細圓體`
6. `華康圓體 Std W3`
7. `Yuanti TC`
8. `PingFang TC`
9. `Microsoft JhengHei UI`
10. `Noto Sans CJK TC`
11. `Noto Sans TC`

字體匹配忽略大小寫，但不做模糊子字串匹配，以免錯配其他華康字型。

## 字級與行距

預設值：

- 出版社名稱：7.5 pt，正常或中等字重，不使用人工粗體。
- 細節：6.5 pt，正常字重。
- 出版社名稱與第一個細節行之間：1.0 mm。
- 細節行基線間距：字型實際行高的 1.12 倍。

Qt 畫布繼續使用 `pt × 25.4 ÷ 72` 換算毫米。正式輸出使用相同 pt 值與相同候選字體。

## 自動收縮版面演算法

資訊群的頂端與 ISBN 標題頂端對齊。版面計算步驟：

1. 取得實際選中字體的 ascent、descent 與 line spacing。
2. 測量出版社名稱的單行實際高度。
3. 將所有非空細節組成行陣列。
4. 依每行實際高度與 1.12 倍行距計算細節文字框高度。
5. 若沒有出版社名稱，細節框從資訊群頂端開始。
6. 若沒有細節，出版社名稱框結束後不保留任何下方高度。
7. 整個資訊群的外框高度等於可見內容高度，不使用模板預先配置的大型固定高度框。
8. 當內容超過封底安全區可用寬度時，先以單行縮小字級至最低 5.5 pt；仍超出時才允許換行，並產生版面警告。
9. 不以垂直置中方式填滿外框，所有文字均從上方開始排版。

## 群組互動

`back-publisher-heading` 與 `back-publisher-details` 共享 `group_id="publisher-info-stack"`。

編輯器行為：

- 點選任一成員時，顯示整個群組的共同選取框。
- 拖動任一成員會以相同位移移動兩個元素。
- 縮放群組會等比例調整：
  - 兩個元素的相對位置。
  - 文字框寬度。
  - 字級。
  - 行距。
- Delete 會刪除整個群組。
- 隱藏會同時隱藏兩個元素。
- 不提供群組內單行的獨立拖動，避免破壞對齊。

若只有其中一個元素存在，仍以相同 `group_id` 運作。

## 模板位置

- 出版資訊群頂端與 `back-isbn-label` 頂端一致。
- 左邊界位於附加條碼或主條碼右側的固定間距後。
- 有附加碼時，以附加碼右緣為基準。
- 沒有附加碼時，主條碼維持固定模組寬度，右側保留參考圖比例的空間，再放置出版資訊；不得把主條碼拉寬填滿。
- 出版資訊群最大右緣不得超出封底安全區。

## 預覽與輸出一致性

建立共享的 `publisher_info_layout` 計算函式，輸入：

- 可見文字行。
- 字體候選與實際可用字體。
- 字級。
- 可用寬度。
- 起始座標。

輸出：

- heading 的矩形。
- details 的矩形。
- 每行基線或行框。
- 實際採用的字級與行距。
- 是否發生換行或溢出警告。

Qt 畫布與 Pillow 正式渲染都使用這份計算結果，不各自猜測文字框高度。

## 錯誤與回退

- 找不到華康字體時，依候選順序選擇本機字體，不中止作業。
- 找不到任何具體候選時，使用平台 sans-serif，並在專案警告中記錄字體回退。
- 譯者欄位無效或只有空白時視為空值。
- 文字溢出安全區時顯示警告，但不裁掉文字而不通知使用者。

## 測試

### 共享測試

- `CoverMetadata.translator` 的 JSON round-trip。
- 舊 schema-v1 JSON 缺少 `translator` 時正常載入。
- `DFPYuanW5-GB` 與 `DFPYuanW3-GB` 位於候選清單首位。
- 缺少細節時資訊群高度只等於出版社名稱高度。
- 缺少出版社名稱時細節從群組頂端開始。
- 缺少中間行時後續行自動上移。
- 譯者前綴不重複。
- 資訊群不超出安全區。

### 桌面測試

- heading 與 details 左邊界完全一致。
- 選取任一元素時群組框包含兩者。
- 拖動、縮放、隱藏與刪除會同時作用於群組成員。
- 控制框移動後不留下拖影。
- Qt 測得的文字高度與共享版面計算結果一致。

### 輸出測試

- Pillow 渲染使用相同字體角色、字級與行框。
- PDF／DOCX 使用完整的自動收縮資訊群。
- 有／無附加碼兩種情況下，右側資訊群位置正確且主條碼不被拉伸。

## 驗收標準

以使用者提供的參考封底為基準：

- `台灣角川` 與下面每一行文字左側對齊。
- 出版社名稱下方不存在固定空白區。
- 缺少任一資料行時，其餘行緊密向上補位。
- 安裝 `DFPYuanW5-GB` 的電腦必須實際使用該字體。
- 譯者資料可輸入、儲存、重新載入並顯示。
- 編輯器、完整預覽及輸出中的資訊群排列一致。
